# 📋 Правила работы с документацией "Строй-Контроль"

## 🎯 **Общие принципы**

### 1. **Единый стандарт документации**
Все документы должны следовать единой структуре и форматированию для обеспечения консистентности.

### 2. **Актуальность информации**
- Только актуальные документы должны использоваться в разработке
- Устаревшие документы должны быть помечены или удалены
- Все изменения должны быть задокументированы

### 3. **Четкая ответственность**
Каждый документ имеет назначенного ответственного за его актуальность.

## 🔄 **Процесс работы с документацией**

### **1. Создание нового документа**
```bash
1. Проверить наличие похожего документа
2. Определить категорию и ответственного
3. Создать файл по правилам именования
4. Заполнить обязательные секции
5. Добавить в README.md
6. Уведомить команду
```

### **2. Обновление существующего документа**
```bash
1. Проверить текущую версию
2. Создать backup текущей версии
3. Внести изменения
4. Обновить версию документа
5. Добавить changelog
6. Запросить review у ответственного
```

### **3. Удаление документа**
```bash
1. Проверить зависимости
2. Уведомить команду за 24 часа
3. Удалить из README.md
4. Переместить в archive/ (если нужно)
5. Обновить все ссылки
```

## 🔍 **Контроль качества**

### **Checklist перед публикацией**
- [ ] Структура соответствует стандарту
- [ ] Все ссылки работают
- [ ] Код компилируется/работает
- [ ] Диаграммы отображаются корректно
- [ ] Версия обновлена
- [ ] Ответственный назначен
- [ ] README.md обновлен

### **Процесс Review**
1. **Self-review** - автор проверяет документ
2. **Peer review** - коллега проверяет техническую часть
3. **Lead review** - ответственный утверждает изменения
4. **Final approval** - документ публикуется

## 🚨 **Частые ошибки и как их избежать**

### **Ошибка 1: Дублирование информации**
**Проблема**: Одна и та же информация в нескольких документах
**Решение**: Использовать ссылки и референсы
```markdown
См. детальную архитектуру в [ARCHITECTURE.md](./ARCHITECTURE.md#backend-architecture)
```

### **Ошибка 2: Устаревшая информация**
**Проблема**: Документ не соответствует текущей реализации
**Решение**: Регулярный аудит документации
```markdown
**Актуально на**: 2024-01-01  
**Следующая проверка**: 2024-02-01
```

### **Ошибка 3: Отсутствие контекста**
**Проблема**: Документ без объяснения "зачем"
**Решение**: Всегда начинать с обзора и целей

### **Ошибка 4: Сложный язык**
**Проблема**: Документ понятен только автору
**Решение**: Простые формулировки и примеры
