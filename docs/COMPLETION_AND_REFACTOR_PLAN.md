# План доработки и завершения проекта

## 1) Frontend (сайт + приложение)
- Унифицировать дизайн-токены (цвета, типографика, отступы, радиусы) в едином слое `tailwind.config.js` + CSS variables.
- Разделить крупные страницы на модульные блоки (Hero, Features, FAQ, CTA) и переиспользуемые компоненты.
- Добавить системную адаптивность: mobile-first брейкпоинты, проверка критичных сценариев на 360/768/1024/1440.
- Внедрить визуальные регрессионные тесты для ключевых страниц.

## 2) Рефакторинг архитектуры frontend
- Убрать дублирование API-вызовов через единый слой сервисов (`src/services`) и хуки запросов (`react-query`).
- Вынести общие UI-примитивы (карточки, секции, таблицы, индикаторы статуса) в библиотеку компонентов.
- Добавить строгие типы DTO/VM и границы ответственности между page/container/presentational.
- Оптимизировать производительность: lazy-load тяжёлых модулей, мемоизация, контроль bundle size.

## 3) Backend (Go + AI Gateway)
- Привести контракты API к единому формату ошибок/валидации/метаданных.
- Формализовать жизненный цикл транзакций и платежей (идемпотентность, повторные запросы, audit trail).
- Усилить observability: бизнес-метрики, трассировка критичных маршрутов, error budget.
- Повысить устойчивость AI-пайплайна: retries, rate-limits, fallback модели, кэширование ответов.

## 4) Качество и тестирование
- Закрыть baseline по тестам:
  - unit: бизнес-логика сервисов/хендлеров;
  - integration: auth, project, finance, ai endpoints;
  - e2e: ключевые пользовательские сценарии от лендинга до рабочих модулей.
- Ввести quality gates в CI: lint, typecheck, test coverage threshold, security scan.

## 5) Безопасность
- Проверить секреты/ключи, перевести в secret manager и ротацию.
- Закрыть требования по RBAC, JWT TTL/refresh policy, rate limiting и CORS.
- Провести аудит OWASP Top-10 (frontend + backend + gateway).

## 6) Delivery и завершение
- Сформировать релизные этапы:
  1. UI/UX стабилизация и адаптив;
  2. архитектурный рефакторинг frontend;
  3. стабилизация backend и AI gateway;
  4. нагрузочное тестирование и hardening;
  5. production release + пост-релизный мониторинг.
- Для каждого этапа зафиксировать DoD (Definition of Done), метрики успеха и дедлайны.
